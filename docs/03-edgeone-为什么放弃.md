# 03 · 为什么放弃了 EdgeOne Pages

这一段是弯路，但值得记录 —— 它解释了「免费域名 + 免备案 + 大陆可访问」
为什么走不通，也解释了最终为什么选自建服务器。

## 一、最初的想法

用腾讯云 **EdgeOne Pages** 免费托管：

- 免费额度永久提供
- 官方支持 Astro，连 GitHub 仓库就能自动部署
- 自带默认子域名（形如 `xxx.edgeone.dev`），**不用买域名**
- 看起来是「零成本上线」的理想方案

## 二、撞上的第一个问题：403 / 401

部署成功、本地访问正常，但**别人打不开**。手机能看到，分享给朋友就报：

```
401: UNAUTHORIZED
Access Restricted or Authentication Expired.
```

查官方文档后找到原因 —— **EdgeOne 的免费默认域名对大陆访问是受限的**。

官方原文（[域名管理概览](https://edgeone.cloud.tencent.com/pages/document/175191784523485184)）：

> **注意：** 为保障内容合规，通过**项目域名**及**部署域名**访问 Pages 站点需遵循以下规则：
>
> 1. 项目加速区域设置为「**中国大陆可用区**」或「**全球可用区（含中国大陆）**」：
>    1.1 须使用系统生成的**预览链接**进行访问，该链接**有效期为 3 小时**，超时后将返回 401 错误
> 2. 项目加速区域设置为「**全球可用区（不含中国大陆）**」：
>    2.1 非中国大陆网络环境可直接访问，**中国大陆网络环境将返回 401 错误**
>
> **建议绑定自定义域名以建立稳定访问通道**，全球可用区（不含中国大陆）**无需备案**。

翻译成人话：

| 加速区域 | 默认域名在大陆 |
| --- | --- |
| 全球可用区（不含大陆） | ❌ **401** |
| 全球可用区（含大陆） | ⚠️ 只有 3 小时预览链接，超时即 401 |
| 中国大陆可用区 | ⚠️ 同样只有 3 小时预览链接 |

**无论选哪个区域，免费默认域名都无法给大陆提供稳定访问。**

而之所以我们自己测试时正常、别人打不开，是因为测试时处于登录态
（控制台会话）或走了代理 —— 平台把请求识别为非大陆网络。

## 三、第二个问题：备案是绕不过的

既然默认域名不行，就绑自己的域名。但绑定域名时弹出：

> 检测到当前域名未在工信部备案，将无法顺利添加

查官方备案文档，结论很明确：

> **一、ICP备案要求说明**
>
> 1. 依据中国《互联网信息服务管理办法》等相关法律法规，使用腾讯云 EdgeOne
>    产品加速服务时，当加速区域为「**全球可用区**」或「**中国大陆可用区**」的
>    域名**必须完成 ICP 备案**
>
> 2. 未 ICP 备案域名，加速区域**不可选**全球可用区或中国大陆可用区，
>    仅可选择全球可用区（不含中国大陆）

**这是法规要求，不是平台政策，换任何账号、任何云厂商都一样。**

所以三条路摆在这里：

| 想要 | 代价 |
| --- | --- |
| 大陆节点加速 | **必须备案**（1–3 周） |
| 免备案 | 只能用「不含大陆」区域，走海外节点（约 200ms） |
| 免备案 + 快 | **自建香港/境外服务器** |

## 四、那「免费 + 免备案 + 境外节点」呢

理论上可行：EdgeOne 选「全球可用区（不含中国大陆）」，绑自己的域名，
免备案，走海外节点。实测有人反馈国内延迟约 200ms
（见 [迁移记录](https://www.iliu.org/posts/migrated-my-blog-to-edgeone-pages/)），
比 Cloudflare 免费版好，但明显慢于大陆/香港节点。

**但这里有个关键点**：这条路**同样需要自己的域名**——免费子域名在大陆仍是 401。

既然域名必须买、备案可以免，那**用自建香港服务器**（约 30–60ms）
就比 EdgeOne 海外节点（约 200ms）更快，而且这台服务器本来就在跑别的项目，
不用额外花钱。

**于是最终方案定为：阿里云香港服务器 + 自建 Nginx。**

## 五、EdgeOne 适合什么场景

不是说它不行，只是**不适合这个项目**：

| 场景 | 是否合适 |
| --- | --- |
| 面向海外用户 | ✅ 很合适，免费、自动部署 |
| 面向大陆用户、愿意备案 | ✅ 合适，能用大陆节点 |
| 面向大陆用户、不愿备案 | ⚠️ 只能走海外节点，偏慢 |
| 不想买域名 | ❌ 默认域名在大陆不可用 |

**优点值得肯定**：免费额度永久、Astro 官方支持、中文控制台、
连 GitHub 自动部署、自带 HTTPS。**如果访客不在大陆，我会推荐它。**

## 六、这次弯路的价值

虽然没走通，但逼出了几个明确结论：

1. **「免费 + 免备案 + 大陆稳定访问」三件事不可能同时成立**
   —— 这是法规层面的约束，不是技术问题
2. **备案的唯一绕法是境外服务器**，香港是最优选择（近、免备案、速度可接受）
3. **域名怎么都得买**（想让大陆用户稳定访问的话）
4. **先查平台文档再动手** —— 这次是先部署、遇到 401、才去查文档，
   如果一开始就查，能省下几轮折腾

## 七、EdgeOne 的构建设置（留作参考）

如果以后要部署面向海外的站点，这些配置是验证过的：

| 配置项 | 值 |
| --- | --- |
| 框架预设 | Astro |
| 构建命令 | `pnpm build` |
| 输出目录 | `dist` |
| 安装命令 | `pnpm install` |
| Node 版本 | 从**预装列表**里选（24.5.0 / 22.17.1） |

**两个坑**（都已解决，代码里有防御）：

1. **不要放 `.nvmrc`**
   —— 平台会去下载它指定的版本，若不在预装列表内（如 24.12.0），
   构建会在「安装依赖」阶段直接失败。
   错误信息：`Switching error: Failed to switch to Node.js 24.12.0`

2. **`pnpm-workspace.yaml` 要带 `packages` 字段**
   —— pnpm 11 会往里写 `minimumReleaseAgeExclude`，但它生成的版本缺少
   `packages` 字段，会让 pnpm 9（平台支持的版本）报
   `packages field missing or empty`
