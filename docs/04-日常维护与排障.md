# 04 · 日常维护与排障

## 一、三条常用命令

```bash
# 更新网站（改了代码、照片、文案之后）
cd /home/admin/laoma-orchard && git pull && ./deploy/publish.sh

# 站点打不开时：一键诊断 + 恢复
sudo ./deploy/recover.sh

# 确认站点状态
curl -sSI https://laoma-apples.site/ | head -1
```

## 二、日常更新网站内容

### 改文案 / 联系方式

编辑 `src/data/site.json`，然后发布：

```bash
git add -A && git commit -m "更新联系方式" && git push
# 服务器上
cd /home/admin/laoma-orchard && git pull && ./deploy/publish.sh
```

### 换照片

1. 把新照片放进 `src/assets/photos/`
2. 在 `src/data/photos.json` 里登记（顺序、说明文字、alt）
3. 发布

> 改图片会让**首次构建变慢**（要重新生成几百个尺寸变体）。
> 只是改文字则很快（图片缓存被复用）。

### 改域名

**只改一处**：`astro.config.mjs` 里的 `site`，然后重新发布。

canonical、og:url、JSON-LD、sitemap、robots.txt 都从它派生，
不会出现改了一处忘另一处的问题。

## 三、发布流程在做什么

`./deploy/publish.sh` 会依次：

| 阶段 | 内容 |
| --- | --- |
| 1/4 构建 | `pnpm build`（含类型检查、静态校验） |
| 2/4 校验产物 | 门禁：无占位域名、`_astro` 全部带哈希 |
| 3/4 发布 | 产物门禁 → 备份上一版 → rsync 同步 → 重载 Nginx |
| 3.5/4 **自检** | 检查站点内容完整性，**不通过则自动回滚** |
| 4/4 完成 | — |

### 产物门禁（发布前，拦住坏产物）

| 检查 | 阈值 |
| --- | --- |
| `dist/index.html` 存在 | — |
| 其体积 | ≥ 5000 字节（真实约 66570） |
| `dist/_astro` 文件数 | ≥ 50（真实 339） |

任一不满足**直接中止，不做任何同步动作**。

### 发布后自检（发布后，发现问题就回滚）

| 检查 | 失败后果 |
| --- | --- |
| 站点目录有 `index.html` 且 ≥ 5000 字节 | 回滚 |
| 页面引用的 `_astro` 资源真实存在 | 回滚 |
| 线上地址返回 200 | **只提示，不回滚**（可能是网络问题） |

**自动回滚**：从 `<站点目录>.prev` 恢复上一版，站点保持发布前状态。

### 手动回滚

```bash
rm -rf /home/admin/mizuno-ami-tiger/laoma-apples
mv /home/admin/mizuno-ami-tiger/laoma-apples.prev /home/admin/mizuno-ami-tiger/laoma-apples
sudo docker exec mizuno-ami-tiger-nginx-1 nginx -s reload
```

## 四、HTTPS 证书

### 当前状态

| 域名 | 到期 |
| --- | --- |
| `laoma-apples.site` | 2027-01-07 |
| `mizunoamitiger.me` | 2027-01-07 |

由 **Let's Encrypt** 免费签发，**自动续期**（`certbot.timer`）。

### 续期机制与副作用

续期需要独占 80 端口做校验，因此**续期时会短暂停止 Nginx 容器
（约 10–30 秒）**，每 60 天一次。钩子保证无论成败都会把容器拉起来。

### 检查续期是否正常

> 证书由 [Let's Encrypt](https://letsencrypt.org/zh-cn/) 免费签发，
> 客户端是 [Certbot](https://certbot.eff.org/)。


```bash
# 演练一次续期，不真正换证书
sudo certbot renew --dry-run

# 看续期定时器
systemctl list-timers | grep certbot
```

### 证书出问题时

```bash
# 看证书有效期
sudo openssl x509 -enddate -noout \
  -in /home/admin/mizuno-ami-tiger/nginx/ssl/laoma-fullchain.pem

# 重新申请本站证书
cd /home/admin/laoma-orchard && sudo ./deploy/server-setup.sh

# 重新申请另一个域名的证书
cd /home/admin/laoma-orchard && sudo EXISTING_DOMAIN=mizunoamitiger.me ./deploy/fix-existing-cert.sh
```

> **不要买付费证书。** Let's Encrypt 免费且自动续期，对这个项目完全够用。

## 五、排障

### 站点打不开

**第一步，跑诊断脚本**：

```bash
cd /home/admin/laoma-orchard && sudo ./deploy/recover.sh
```

它会依次检查并打印：容器状态、挂载映射、两端文件数、端口监听、磁盘占用、
证书状态，然后尝试恢复。**把输出保存下来，这是排查的依据。**

### 手动分层排查

```bash
# 1. 容器是否在跑
sudo docker ps --filter name=mizuno-ami-tiger-nginx-1

# 2. 容器日志（最有用）
sudo docker logs --tail 30 mizuno-ami-tiger-nginx-1

# 3. 端口是否在监听
sudo ss -lntp | grep -E ':(80|443) '

# 4. Nginx 配置是否正确
sudo docker exec mizuno-ami-tiger-nginx-1 nginx -t

# 5. 容器内能否看到站点文件
sudo docker exec mizuno-ami-tiger-nginx-1 \
  sh -c 'find /usr/share/nginx/laoma-apples -type f | wc -l'
# 应输出 300 多

# 6. 挂载是否正确
sudo docker inspect mizuno-ami-tiger-nginx-1 \
  --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
```

### 常见现象对照

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 404（Nginx 默认页） | 站点目录为空 | 跑 `publish.sh` 重新发布 |
| 502 / 503 | 容器没起来 / 后端挂了 | 看容器日志，`recover.sh` |
| 连不上（超时） | 容器停止 / 防火墙 | 看端口监听，检查阿里云防火墙 |
| 证书报错 | 证书过期 | 见上「证书出问题时」 |
| 页面样式错乱 | 资源没同步完整 | `publish.sh` 会自检并回滚 |

## 七、改配置时的注意事项

### 改 Nginx 配置

配置文件里的 `# LAOMA-ORCHARD-BEGIN` 与 `# LAOMA-ORCHARD-END`
是本站块的边界标记，**不要手工删掉其中一个**——`patch_nginx.py` 靠它们
识别并替换自己的块。要改配置，改 `deploy/nginx-laoma-*.conf`
然后重跑 `server-setup.sh`。

### 改完后一定要校验

```bash
# 先静态校验片段（本机也能跑，不需要 nginx）
python3 deploy/validate_nginx.py deploy/nginx-laoma-http.conf deploy/nginx-laoma-https.conf

# 应用后校验容器内配置
sudo docker exec mizuno-ami-tiger-nginx-1 nginx -t
```

### 不要动的东西

| 别动 | 原因 |
| --- | --- |
| 现有 nginx.conf 里 `server_name _` 的块 | 别的项目在用 |
| `default_server` | 会接管整个端口的未定义域名 |
| `docker-compose.prod.yml` | 原始配置，脚本读它生成 effective 版 |
| `laoma-apples.prev` | 发布失败时的救命备份 |
