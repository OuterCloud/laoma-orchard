# 02 · 服务器部署

## 一、目标

把站点部署到已有业务的服务器上，**不影响现有项目**，且能做到
「服务器上 `git pull` 后跑一条脚本就完成部署」。

服务器控制台：<https://swas.console.aliyun.com/>
（公网 IP、实例状态、防火墙都在这里）

本次的服务器状况（部署前）：

```
阿里云轻量应用服务器（香港）  47.239.154.107
Docker Compose 跑着另一个项目：
  mizuno-ami-tiger-nginx-1     nginx:alpine     占用 80/443
  mizuno-ami-tiger-backend-1   后端             127.0.0.1:8002
  mizuno-ami-tiger-frontend-1  前端（仅内网）
```

**关键约束**：80/443 已被占用，且现有 Nginx 用的是 `server_name _`（通配）。

## 二、整体思路

利用 Nginx 的**基于域名的虚拟主机**：多个 server 块可以监听同一个端口，
Nginx 按请求头里的 `Host`（用户访问的域名）分发。

```
80/443（同一个 Nginx 容器）
  ├─ server_name laoma-apples.site  → 我们的静态文件
  ├─ server_name mizunoamitiger.me  → 现有项目（不动）
  └─ server_name _                  → 原有通配块（不动）
```

因此**只需追加我们自己的 server 块，不改动现有配置一行**。

## 三、部署步骤

### 前置：装 Node 22

站点用 Astro 构建，服务器需要 Node >= 22.12。

```bash
cd /home/admin/laoma-orchard
sudo ./deploy/bootstrap-node.sh
hash -r          # 刷新 shell 的命令缓存
node -v          # 应显示 v22.x
```

`bootstrap-node.sh` **不经过 apt**，直接下载 Node 官方预编译包并按
官方 `SHASUMS256.txt` 校验 SHA256，解压到 `/usr/local`。
（为什么不用 apt：见 [05-踩坑记录.md](05-踩坑记录.md)）

### 第一步：克隆项目

```bash
cd /home/admin
git clone git@github.com:OuterCloud/laoma-orchard.git
cd laoma-orchard
```

### 第二步：一次性初始化

```bash
sudo ./deploy/server-setup.sh
```

脚本会自动完成 8 步：

| 步骤 | 内容 |
| --- | --- |
| 0 | 前置检查（现有配置、容器、公网 IP） |
| 1 | 创建目录（站点目录 + ACME 校验目录） |
| 2 | 备份现有 nginx.conf 与 compose 文件 |
| 3 | **静态校验**后追加我们的 server 块（HTTP 阶段） |
| 4 | 生成合并后的 compose 文件（加两个只读挂载） |
| 5 | 应用挂载、校验 nginx 配置、重载 |
| 6 | 申请 HTTPS 证书（standalone） |
| 7 | 检查构建环境 |
| 8 | 构建并发布静态文件 |

### 第三步：日常更新

```bash
cd /home/admin/laoma-orchard
git pull && ./deploy/publish.sh
```

### 第四步（可选）：修另一个域名的过期证书

如果服务器上原有项目的证书也过期了：

```bash
sudo EXISTING_DOMAIN=mizunoamitiger.me ./deploy/fix-existing-cert.sh
```

## 四、脚本清单

| 文件 | 作用 |
| --- | --- |
| `server-setup.sh` | 一次性初始化。参数：`--install-node`（缺 Node 时自动装）、`--yes` |
| `publish.sh` | 日常发布。构建 → 门禁 → 备份 → 同步 → 重载 → **自检+自动回滚** |
| `recover.sh` | 一键恢复 + 诊断。站点打不开时先跑它 |
| `bootstrap-node.sh` | 安装 Node（官方包，不走 apt） |
| `fix-existing-cert.sh` | 修服务器上已有域名的过期证书 |
| `nginx-laoma-http.conf` | 第一阶段 server 块（仅 80 端口） |
| `nginx-laoma-https.conf` | 第二阶段 server 块（HTTP + HTTPS） |
| `patch_nginx.py` | 把上述片段幂等插入现有 nginx.conf，不改动既有行 |
| `merge_compose.py` | 生成「原 compose + 两个只读挂载」的最终文件 |
| `validate_nginx.py` | Nginx 配置静态校验（本机无 nginx 也能查） |

## 五、为什么分成两阶段配置

**Nginx 在启动时就要求 `ssl_certificate` 指向的文件必须存在。**

如果一开始就把 443 的 server 块写进去，而证书还没申请，容器会因缺证书
**启动失败并反复重启**。所以：

1. 先只装 80 端口的块（含 ACME 校验路径）
2. 证书签发成功后，再替换为 HTTP + HTTPS 版本

`patch_nginx.py` 靠开始/结束标记识别自己的块，替换而非累加——重复执行安全。

## 六、如何保证不影响现有项目

| # | 措施 |
| --- | --- |
| 1 | **不修改现有 nginx.conf 任何一行**，只在 `http {}` 收尾花括号前插入自己的 server 块 |
| 2 | **精确域名匹配** —— 现有配置是 `server_name _` 通配，精确名优先，不会抢请求 |
| 3 | **只给 nginx 服务加两个只读挂载**，backend / frontend 容器完全不动 |
| 4 | 只 `nginx -s reload`，不 restart（重载是平滑的） |
| 5 | 改动前**自动备份**，配置校验失败**自动回滚** |
| 6 | 发布后有**自检 + 自动回滚**，静默失败也不会挂站 |
| 6 | 全程**幂等**，重复执行不会累积重复配置 |

### 一条重要教训：不要声明 default_server

`default_server` 是**监听端口的属性，不是 server_name 的属性**——
声明它等于「接管这个端口上所有未定义的域名」。

我一开始为解决 ACME 校验被通配块接走的问题，给我们的块加了
`default_server`，结果**所有未匹配的域名（包括在用的 `mizunoamitiger.me`）
都落到我们的块上并命中 `return 503`**，把现有站点搞挂了。

**正确做法**：不碰默认 server，证书改用 standalone 方式申请（见下）。

## 七、证书申请：为什么用 standalone 而不是 webroot

现有配置的 80 端口块是 `server_name _` 且只做 301 跳转，
**ACME 校验请求会被它接走并跳转到 HTTPS**，certbot 拿不到校验文件。

因此改用 `--standalone`：申请瞬间独占 80 端口。

**代价**：需短暂停止 Nginx 容器 **10–30 秒**。脚本用 `trap` 保证
**无论成败都会把容器拉起来**，不会留下停服状态。

自动续期同理，通过 pre/deploy 钩子停容器再拉起，每 60 天一次。

> **钩子必须容错**：所有命令以 `|| true` 结尾并显式 `exit 0`。
> 曾因钩子里的 `nginx -s reload` 失败（此时容器正被停着）导致 certbot
> 整体返回非 0，**证书明明签发成功却被判为失败**。详见 [05-踩坑记录.md](05-踩坑记录.md)。

## 八、防火墙

**阿里云轻量应用服务器有独立的防火墙**，默认可能只开 22 端口。

控制台入口：**<https://swas.console.aliyun.com/>**
（[轻量应用服务器控制台](https://swas.console.aliyun.com/) → 实例 → 防火墙）

或从 [阿里云控制台首页](https://home.console.aliyun.com/) 进入。

**添加规则**：

| 应用类型 | 端口 |
| --- | --- |
| HTTP | 80 |
| HTTPS | 443 |

**不做这步，解析配对了也打不开**——这是最常见的卡点。

## 九、部署后的目录结构

```
/home/admin/mizuno-ami-tiger/          ← 现有项目（未改动）
├── docker-compose.prod.yml
├── docker-compose.effective.yml       ← 脚本生成（含我们的挂载）
├── nginx/
│   ├── nginx.conf                     ← 追加了我们的 server 块
│   ├── nginx.conf.bak-<时间戳>         ← 自动备份
│   ├── acme/                          ← ACME 校验目录
│   └── ssl/
│       ├── fullchain.pem              ← 现有域名证书
│       ├── privkey.pem
│       ├── laoma-fullchain.pem        ← 本站证书
│       └── laoma-privkey.pem
├── laoma-apples/                      ← 本站静态文件（挂载进容器）
└── laoma-apples.prev/                 ← 上一版备份（发布失败可回滚）

/home/admin/laoma-orchard/             ← 项目代码
├── src/  dist/  deploy/  docs/
```
